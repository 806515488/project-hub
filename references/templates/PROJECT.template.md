## 自维护规则（发现偏差直接修复，无需询问、无需任何外部 skill）

- 仓库内文档 > 工具本地记忆 > AI 自由发挥
- **开场对账**：会话开始先读 docs/status.md 并对照 `git log --oneline -10` 与 `git status`；只补记**本机会话漏账的改动**（带 `[工具名]` 前缀的提交、或本机工作区未提交改动）。他人提交不补记；归属不明的先问用户——宁可漏记，不可错记
- status.md 只留当前态，历史交给 git；任务收尾必须更新它
- **信息落点**：记录任何信息前按 docs/conventions.md「信息落点」路由写入对应文档；禁止向入口文件（CLAUDE.md / AGENTS.md 等）写入正文
- **凭据不落文档**：任何文档（含样板示例、笔记、坑区）禁止出现真实凭据——密码、token、API key、连接串一律写占位符（如 `<PASSWORD>`）；真实值只存在于环境变量 / 配置中心
- 入口文件缺失或内容被改动 → 按 docs/conventions.md「入口文件标准」补齐或改回指向；发现入口文件出现正文 → 内容按路由迁移归位，入口恢复为指向
- 任一文档超 300 行 → 拆分并更新本文件索引
- 本文件超 60 行 → 先合并同类索引行（如多个「专题-X.md」合并为目录级一行）；仍超说明项目过大，与用户商量拆子体系，不硬塞
- 索引指向的文件不存在 → 先修正索引；若内容疑似被误删，记入 status.md 挂起问题
- 落文档只写结果，坑一行一条（格式见 docs/conventions.md 落文档纪律）
- AI 修改本文件结构需用户确认（上述机械性修复除外）
